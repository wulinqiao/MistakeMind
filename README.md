# MistakeMind

面向学生的中文病句诊断、修改与个性化训练 Agent。

## 题库在哪里

练习候选题共有 **120 道**：原有 [20 道八类/正常句候选](data/questions.json)，新增 [100 道 CS2W 语法候选补充](data/external/cs2w_grammar_candidates.json)。请从 [题库总目录](data/README.md) 查看数量、来源与审核状态。它们目前仍待项目教学审核；B 模块评测数据与练习题库分开保存。

运行 `python -m scripts.list_question_banks` 可校验并查看全部练习候选题数量。

MistakeMind 不只是给出一个“正确答案”，而是围绕学生的错误形成完整训练闭环：

```text
练习 → 作答 → 诊断 → 提示 → 讲解 → 变式训练 → 错题记录 → 个性化复习
```

## 项目背景

传统病句练习通常只返回对错或标准答案，学生难以知道自己具体错在哪里，也很难持续追踪同类错误。通用大模型虽然可以生成修改建议，但可能过度修改、改变原意，或者给出不稳定的解释。

MistakeMind 面向中学生的病句专项训练场景，重点解决三个问题：

1. 准确判断句子是否存在语病，并定位错误位置；
2. 根据学生答案解释错误原因，而不是只展示答案；
3. 根据历史表现推荐相似题，帮助学生减少重复错误。

## 核心功能

- **病句诊断**：判断是否为病句，识别错误位置和错误类型。
- **最小修改**：尽量少改字并保持原意，提供一种或多种合理修改。
- **分层提示**：先提示错误位置，再提示知识点，最后提供修改方向。
- **学生训练**：支持判断题、选择题和自主修改题。
- **错题记录**：保存学生答案、诊断结果、错误类型和训练时间。
- **个性化推荐**：根据薄弱知识点推荐下一道练习题。
- **学习统计**：展示各类病句的正确率、错误次数和掌握情况。
- **Agent 轨迹**：记录路由、工具调用、结构校验和持久化过程，方便调试与课堂展示。

## 支持的病句类型

MVP 阶段支持：

- 成分残缺
- 成分赘余
- 搭配不当
- 语序不当
- 结构混乱
- 表意不明
- 不合逻辑
- 关联词使用不当

后续可扩展结构杂糅、标点错误、词语误用和篇章级表达问题。

### Agent 职责

| Agent | 主要职责 |
| --- | --- |
| 任务路由 Agent | 识别诊断、练习、复习和统计等任务 |
| 病句诊断 Agent | 判断病句、定位错误并分类 |
| 学生答案分析 Agent | 比较学生答案与参考答案，识别知识点掌握情况 |
| 分层提示 Agent | 按提示等级引导学生自主修改 |
| 最小修改 Agent | 生成保持原意的修改方案 |
| 复核 Agent | 检查新语病、语义变化和 Schema 完整性 |
| 推荐 Agent | 根据历史表现选择下一道练习题 |

## 统一输出 Schema

```json
{
  "has_error": true,
  "error_types": ["结构混乱", "主语残缺"],
  "error_span": "通过……使……",
  "explanation": "“通过”和“使”同时使用，导致句子结构混乱。",
  "corrections": [
    "通过开展此次活动，同学们提高了环保意识。",
    "开展此次活动，使同学们提高了环保意识。"
  ],
  "needs_context": false,
  "review_flag": true
}
```

所有 Agent 应尽量返回结构化 JSON，由 Pydantic 进行字段校验，避免前端直接解析不稳定的自然语言输出。

## API 规划

| API | 作用 |
| --- | --- |
| `POST /api/diagnose` | 诊断句子并返回病句分析 |
| `GET /api/questions` | 按类型和难度获取练习题 |
| `POST /api/submit-answer` | 提交学生答案并更新训练记录 |
| `GET /api/history/{user_id}` | 查询学生历史答题和解析 |
| `GET /api/profile/{user_id}` | 查询错误画像和推荐知识点 |

## 数据结构

- `questions`：题目、病句类型、参考修改、难度和来源。
- `attempts`：学生作答、是否正确和作答时间。
- `diagnoses`：错误类型、解释、修改建议和复核结果。
- `users`：学生昵称和基础信息。

## 实验设计

项目设置三组对照：

1. **Baseline**：直接调用普通 LLM；
2. **实验 A**：结构化 Prompt + 固定病句标签 + 结果校验；
3. **实验 B**：实验 A + 检索工具 + 学生历史信息。

建议报告以下指标：

- 病句判断 Precision / Recall / F1；
- 病句类型 Macro-F1；
- 有效修改比例；
- 语义保持率；
- 推荐题目命中薄弱知识点的比例；
- 接口成功率和平均响应时间。

测试集建议包含 60—100 道人工审核题目，覆盖主要病句类型、非病句和存在多种合理修改的边界案例。每道题至少标注是否为病句、错误类型、错误片段、参考修改、难度和来源。

## 运行计划

当前仓库先完成项目文档和协作基础设施。代码模块将按项目计划逐步补齐。正式运行前需要配置：

```text
LLM_API_KEY=你的模型服务密钥
LLM_BASE_URL=模型服务地址
DATABASE_URL=sqlite:///./data/mistakemind.db
```

不要把真实 API Key 提交到 Git。建议使用 `.env` 文件，并将其加入 `.gitignore`。

## D 模块后端启动

D 模块已提供 FastAPI、SQLite、统一 Pydantic Schema、题库导入和 Mock Agent 闭环。安装依赖后运行：

```powershell
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
uvicorn backend.main:app --reload
```

服务地址为 `http://127.0.0.1:8000`，健康检查为 `/health`，接口文档为 `/docs`。也可以使用 `start.ps1` 或 Dockerfile 启动。未配置 `LLM_API_KEY` 时使用确定性 Mock 诊断，便于前后端联调；完整请求、响应、错误码和题库导入说明见 [`docs/api.md`](docs/api.md)。

## 项目边界说明

当前 MVP 暂不包含 OCR、作文篇章级批改、模型微调和复杂知识图谱。优先保证单句病句训练闭环、结构化输出、历史记录、推荐逻辑和实验可复现。
