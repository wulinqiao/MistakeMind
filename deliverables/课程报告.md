# 基于大语言模型与练习反馈的病句诊断智能体设计与实现

**项目名称：** MistakeMind  
**版本：** v1.2  
**应用场景：** 中学生中文病句专项训练  
**主要技术：** Vue 3、FastAPI、Pydantic、SQLite、兼容 Chat Completions 协议的大模型服务

---

## 摘要

MistakeMind 面向中学生病句专题训练，将句子诊断、作答评判、修改解释、记录保存与针对性复练组织为完整的 Web 学习流程。传统练习往往只返回对错或标准答案；通用大模型虽能生成改写，却容易过度修改、改变原意或解释不稳定。本系统采用“确定性程序主控 + 大模型语义子任务”的路线：前端负责训练交互，后端负责接口校验与业务编排，智能体流水线完成路由、诊断、提示、修改、答案分析与复核，数据库与结构化题库承担持久化。模型输出必须通过字段校验与可靠性门控；不确定结论显式标记为待复核，不得静默计入成绩或学习画像。

系统覆盖八类病句与正常句，支持判断题、选择题与修改题。正式练习库包含 64 个不同句子、三种题型共 192 条记录；模型评测使用独立的 79 条人工审核样本，与练习数据隔离。真实对照实验表明：在固定测试集上，结构化诊断加复核并未整体优于通用指令基线。工程回归与浏览器验收证明学习闭环可用，但不能把离线固定样例或接口测试通过率当作语文诊断精度。本文说明任务界定、系统架构、应用逻辑、智能体设计、数据与推荐、评测结果、部署运维及团队分工。

**关键词：** 病句诊断；大语言模型；智能体编排；结构化输出；复核门控；个性化推荐；教育测评

## 1 引言

### 1.1 背景与动机

中学语文教学中，病句辨析是常见专项。普通练习通常给出标准答案，学生难以定位错误片段，也难以理解自己本次作答错在何处；连续练习又缺少按错误类型沉淀的历史与复练引导。直接调用通用大模型改写，则存在过度修改、改变原意、同类句子解释不稳定等问题。MistakeMind 面向中学生病句专项训练，重点解决三个问题：

1. 判断句子是否存在语病，并定位错误位置与类型；  
2. 结合学生答案解释错误原因，而不是只展示标准答案；  
3. 根据历史表现推荐相似练习，减少同类错误反复出现。

### 1.2 目标与学习闭环

系统围绕如下闭环组织功能，而不是孤立地调用一次大模型：

```text
练习 → 作答 → 诊断 → 提示 → 讲解 → 变式训练 → 错题记录 → 个性化复习
```

对应能力包括：句子诊断、修改建议、作答评判、题库训练、历史错题、针对性推荐、知识画像，以及可展开的智能体执行轨迹。自动追问或自动生成未经审核的标准新题不作为本期必做内容。

### 1.3 语病类型与范围

本期支持八类病句（另保留兼容类别“其他”）：成分残缺、成分赘余、搭配不当、语序不当、结构混乱、表意不明、不合逻辑、关联词使用不当。该集合覆盖课程项目计划中的四类目标语病，并扩展至八类。

本期不包含：光学字符识别与拍照批改、模型微调、完整教师端与班级管理、复杂知识图谱、篇章级作文批改。优先保证单句训练闭环、结构化输出、历史记录、推荐逻辑与实验可复现。

### 1.4 用户与运行边界

系统用字符串用户标识区分练习记录，可用于演示与单用户场景，并不构成完整的认证授权体系。运行分为两类，证据效力必须分开表述：

| 模式 | 含义 | 证据效力 |
| --- | --- | --- |
| 离线演示 | 使用固定样例与独立演示库，未知句子一律待复核 | 只证明流程可跑通，不证明诊断精度 |
| 真实模型 | 调用外部大模型服务；失败时不静默退回演示样例 | 精度结论必须来自审核测试集上的真实调用 |

## 2 设计立场

本项目不把“每个逻辑角色各自发起一次独立长对话”当作目标，而采用确定性主控流水线：路由、超时预算、结构校验、事务落库与推荐统计由程序固定；仅在需要语义理解处调用大模型。核心原则如下。

1. **先约定数据结构与接口，再并行开发。** 跨模块字段变更必须先统一约定，再改实现。  
2. **跨模块传递结构化 JSON**，不以不稳定的自然语言文本作为契约。  
3. **统一响应格式与错误码**；前端不猜测未约定字段，后端不返回未约定字段。  
4. **智能体内部可以迭代，对外输出必须符合约定结构。**  
5. **失败必须可解释**：禁止静默吞错；真实服务失败禁止静默切换为演示样例。  
6. **数据隔离**：练习题、评测样本、演示样例三者分离；审核状态不由程序自动升格为正式标准答案。

因此，工程可用性与模型教学质量在后文分章报告，不得互相替代。

## 3 系统总体架构

### 3.1 分层结构

系统自上而下分为四层。

**表现层：** 基于 Vue 3 的训练界面，包含首页筛选、自由诊断、三题型练习、历史错题与学习画像。浏览器不直接访问大模型，也不在本地计算推荐优先级。

**业务接口层：** 基于 FastAPI。负责请求校验、业务编排、统一错误处理，以及生产环境下对前端静态资源的同源托管。开发阶段可由前端开发服务器将接口请求代理到后端。

**智能体编排层：** 按确定性顺序组织路由、诊断、提示、修改、答案分析、复核；推荐由统计规则完成。编排层持有统一上下文对象与执行轨迹，记录各阶段开始、成功或失败。

**资源层：** 大模型 Chat Completions 接口、SQLite 业务库，以及以结构化 JSON 维护的题库与评测集。题库导入时校验字段与审核状态。

### 3.2 模块划分

系统按职责分为四个并行模块：前端与学生训练流程；智能体、提示词与诊断判分逻辑；题库、推荐与评测；后端接口、数据库与部署。四者通过统一接口与数据结构协作，避免前端直接定义语病标签，也避免智能体绕过校验直接写库。

### 3.3 运行与部署

本地提供一键启动脚本，可选择离线演示或读取本地环境配置的真实模型模式。容器方案采用前端构建与后端服务的多阶段镜像，运行时挂载数据目录并注入环境配置；构建过程排除密钥与数据库等敏感或环境相关文件。若实际环境未完成容器验证，不以“存在容器配置”推断部署已通过；本期已验证路径以本地同源生产构建与浏览器完整操作为准。

真实模型密钥仅保存在本地环境配置中，不写入代码仓库，不进入执行轨迹或前端响应。

## 4 完整应用逻辑

### 4.1 端到端学习路径

学生使用系统的主路径如下。

1. **进入应用。** 页面读取运行状态：当前为演示还是真实模型、启用题目数量、是否演示题库，避免把离线样例说成真实诊断。  
2. **自由诊断。** 学生输入句子，系统返回是否病句、错误类型、错误片段、解释、修改建议与分层提示。只有通过复核的结果才作为正式诊断落库。  
3. **选题练习。** 可按难度与题型筛选；若提供用户标识且未指定错误类型，则按近期画像推荐。题面不包含参考修改与标准解释。  
4. **提交作答。** 系统判分后，在同一数据库事务中保存作答与关联诊断，并返回下一题推荐编号与执行轨迹。前端直接展示本次返回的诊断反馈，不再另外发起一次自由诊断来覆盖判题依据。  
5. **精确复练。** 按推荐题号打开下一题，并尽量保持题型与难度一致。  
6. **历史与画像。** 历史支持分页、按类型筛选与“只看错题”；画像展示累计正确率、近期平滑表现、样本是否充足及近两周有作答日期的趋势。刷新页面后从数据库重新读取，以验证持久化。

### 4.2 统一接口语义

业务接口主要包括：句子诊断、按条件取题、按题号精确取题、提交答案、查询历史、查询画像、查询运行状态与健康检查。所有业务响应采用统一外层结构：是否成功、请求编号、业务数据、错误体、以及带时间戳与版本号的元信息。字符编码为 UTF-8，时间为带时区的 ISO 8601，空值使用空值标记而不用空字符串代替。

### 4.3 错误处理与产品后果

| 情形 | 处理原则 |
| --- | --- |
| 参数不合法 | 直接拒绝，不调用模型，不写库 |
| 题目不存在或未启用 | 返回未找到 |
| 模型不可用、鉴权失败或限流 | 明确失败；真实模式不退回演示样例 |
| 模型超时 | 记为失败；实验中不得当作“判对” |
| 模型输出无法解析为约定结构 | 有限次修复后仍失败则报错 |
| 低置信或复核未通过（作答场景） | 提示需要复核，不计成绩、不更新画像 |
| 数据库写入失败 | 事务回滚，不留下半条成绩 |

自由诊断在待复核时可以返回暂定解释供阅读，但不得存为已通过诊断。作答场景的不确定结果不得影响成绩与画像。

### 4.4 防泄题与标签一致

练习取题接口不返回参考修改、标准解释等答案字段。题目类别字段因兼容保留，但对练习前端置空，避免分类选择题直接看到标准类别；服务端仍可按类型筛选题库。判断题选项固定为“是病句 / 不是病句”；选择题选项使用统一的病句类型标签。难度分为小学高年级、初中、高中、综合；题型分为判断题、选择题、修改题。全系统禁止同义词标签漂移。

### 4.5 前端交互要点

页面包括训练入口、练习页、诊断页、历史页与画像页。通用错误提示按错误码给出明确文案；诊断待复核时显示“暂无法确认”，避免把未确认结论展示成已判定结果；执行轨迹可展开，便于说明模型步骤与程序步骤的分工。浏览器完整验收覆盖：固定病句诊断、正常句不强行改写、未覆盖句待复核、分类题不泄题、错答后保存关联解析、推荐题精确跳转且刷新保持、历史筛选与刷新后仍可读取、画像统计可见，以及小屏宽度下无横向溢出。离线演示中的成绩与用户数据只证明交互闭环，不代表真实学习收益。

## 5 智能体系统设计

### 5.1 编排方式

编排服务使用统一上下文，字段包括：请求编号、用户标识、任务类型、年级、原句、学生答案、题目信息、历史摘要、当前结果与执行轨迹。各阶段只修改本职字段，并将事件追加到轨迹。逻辑阶段多，并不意味着每次请求都调用六次模型：常规诊断通常是一次结构化生成（同时得到诊断、修改与提示），再加一次独立复核。标准选择题与命中参考修改的修改题由程序直接判分，不调用模型；开放式修改在真实模式下才进入语义评判与复核。

### 5.2 各阶段职责

| 阶段 | 职责 | 是否调用模型 |
| --- | --- | --- |
| 任务路由 | 区分诊断与作答等路径 | 否 |
| 病句诊断 | 判断语病、定位、分类、解释与置信度 | 演示模式用固定样例；真实模式是 |
| 分层提示 | 给出一至三级提示 | 通常随诊断一次生成 |
| 最小修改 | 生成少改字、保原意的候选改法 | 通常随诊断一次生成 |
| 答案分析 | 标准题确定性判分，或对开放修改做语义评判 | 视题型而定 |
| 复核 | 检查分类依据、是否消错、是否保义、结构是否完整 | 真实诊断与开放修改需要 |
| 推荐 | 按近期薄弱类型选择下一题 | 否，使用统计规则 |

### 5.3 结构化诊断

诊断结果包括：是否病句、错误类型列表、错误片段、解释、修改列表、分层提示、置信度、是否需要更多上下文。正常句返回空错误类型与空修改列表，不强行改写。标签必须来自固定枚举。模型输出先做结构与一致性校验，再进入复核。

### 5.4 分层提示与最小修改

提示分为三级：先提示观察位置，再提示相关知识点，最后给出修改方向。病句允许多种合理改法，目标是消除原语病并尽量保持原意。若修改结果与原句相同，或在需要提示时缺少完整三级提示，则判定不可靠并进入待复核。

### 5.5 作答评判规则

判断题答案必须是“是病句”或“不是病句”，并与题库是否标注错误一致。选择题答案必须是统一类型标签，并与题库标注对齐。修改题优先接受已审核参考修改；其他表达须同时满足：消除原语病、基本保留原意、未引入新语病，并由语义分析与复核共同决定。原病句原样提交不得判对。模式不匹配或空答案直接拒绝。不确定或复核冲突时不计成绩。通过结果与关联诊断同事务保存；关联诊断依据题库标准标签撰写解释，并标明依据来源，不伪装成对原句的重新检测。

### 5.6 可靠性门控

最终复核状态综合以下条件：复核是否批准；是否需要更多上下文；自评置信度是否达到阈值（默认 0.7）；修改是否与原句相同；需要提示时三级提示是否完整。自评置信度只是可配置门槛，不是经过校准的概率；前端展示必须连同复核状态理解，不能仅凭“是否病句”的布尔字段下定论。

### 5.7 提示词、预算与轨迹

提示词集中管理并记录版本。内部输入输出类型与对外业务结构对齐，即使服务端开启 JSON 模式，本地仍做结构校验。默认预算为：单次调用约 20 秒；整笔业务约 60 秒、最多 4 次外部调用；网络或服务端限流错误最多重试一次；格式错误最多修复一次；鉴权类客户端错误不重试。执行轨迹记录模式、模型名、提示词版本、阶段、状态、时间、耗时、调用次数与已报告用量，不记录密钥与原始完整响应。

## 6 数据持久化与题库治理

### 6.1 业务数据

系统持久化用户、题目、作答与诊断。题目保存题面、题型、类别、参考修改、难度、来源与启用状态；教学解释与错误片段等扩展信息可存放于附属结构以保持兼容。作答保存学生答案、正误、提示使用等级与时间。诊断保存错误类型、片段、解释、修改与复核状态，并可关联到某次作答。作答与诊断同事务写入，失败则全部回滚。

### 6.2 三类数据隔离

| 集合 | 内容 | 用途 |
| --- | --- | --- |
| 练习库 | 64 个不同句子，判断、选择、修改三种形式共 192 条记录 | 线上训练 |
| 评测集 | 79 条已审核样本：61 条病句、18 条正常句，含多标签样例，覆盖八类 | 模型对照实验，不进入练习库 |
| 演示库 | 12 个固定句子的三种交互形式，共 36 道 | 离线演示与联调，不计正式语料，不作精度结论 |

练习内容来自项目自编与初高中书面语题型变式，参考公开教学资料整理常见病因，**不是历年中高考原题或教材原题**。曾考虑的口语转写类外部语料因不符合中学书面语教学场景，已撤出练习范围。练习题启用依据用户确认的审核通过决定导出并导入正式库；原始候选可保留追溯，程序不得默认批准任意题目。同一句子展开为三种题型时，复用相同标签与参考修改，不自动编造新例句。

### 6.3 审核与导入原则

候选题目需经审核决定、审核人与带时区的审核时间记录后，方可导出为已审版本并导入正式库。导入前可进行校验演练；正式导入前应备份数据库。评测样本、开发回归样例与指标计算示例数据不得用来充数练习题。若题目内容发生修改，须重新审核，避免“审核旧版、启用新版”。

## 7 个性化推荐与学习画像

### 7.1 推荐算法

推荐使用最近 50 次作答作为近期窗口。对某类别若有 n 次作答、e 次错误，定义平滑错误率 \((e+1)/(n+2)\)，并加入探索项 \(0.15/(n+1)\)。系统先选择优先类别，再在该类内避开近期已做题目；同类不足时允许复练。推荐保持当前题型与难度，返回具体题号供前端精确打开。页面不得把“尚未练习、因探索被抽到的类型”直接说成已确认的薄弱项。

推荐是可审计的统计规则，不是大模型直接选题。

### 7.2 画像含义

画像同时给出累计正确率、错误次数，以及窗口内的平滑正确率估计 \((c+1)/(n+2)\)（c 为答对次数）。某类作答少于 3 次时标注样本不足，避免一次偶然结果被解读为长期能力。趋势展示最近 14 个有作答日期的每日题量与正确率。上述统计只描述练习记录，不推断认知能力，也不构成教学干预因果效应的证据。

## 8 评测设计与实验结果

### 8.1 对照设置

实验比较三组方案：

1. **基线：** 通用诊断指令；为便于自动解析，与结构化组共用同一 JSON 输出约定，因此比较的是通用指令与专用流程，而非任意自由聊天。  
2. **结构化方案：** 增加固定标签定义、教学约束与独立复核。  
3. **完整方案：** 在结构化方案上再引入独立已审工具题库与虚构历史情境。正式完整方案要求工具题与测试句无同题、无近似泄漏；该部分所需独立工具题库与场景审核仍为后续工作，本期不以未完成实验冒充已验证结论。

运行过程逐条记录成功、拒判、失败、耗时、调用轨迹与用量。恢复运行要求数据、配置与代码版本一致；失败重试保留历史记录。正式评测只使用已审核样本。

### 8.2 指标口径

报告接受率、拒判率、失败率；全样本主类别准确率、八类宏平均 F1、多标签微平均 F1。仅统计“被系统接受样本”的分数可另列，但不得替代全样本结果。保守检测计分将拒判或失败的病句计为漏检、将拒判或失败的正常句计为误报，该口径不同于标准混淆矩阵，须单独说明。流程完成率（把待复核算作流程有效、只把失败算未完成）与模型接受率必须分口径表述。另报告平均耗时、外部调用次数与已报告 token；费用以服务商账单为准。修改是否有效、原意是否保持须人工评分后计算，未评分不得填写虚假完成度。

### 8.3 真实对照结果

在同一审核测试集（79 条）与同一模型服务上，完成基线与结构化两组真实调用。未把测试题写入练习库，也未根据本次结果回改提示词后再声称独立验证。主要结果如下。

| 指标 | 通用指令基线 | 结构化与复核 |
| --- | ---: | ---: |
| 接受 / 待复核 / 失败 | 71 / 2 / 6 | 61 / 10 / 8 |
| 接受率 | 89.87% | 77.22% |
| 全样本主类别准确率 | 83.54% | 72.15% |
| 全样本八类宏平均 F1 | 0.8060 | 0.7333 |
| 多标签微平均 F1 | 0.8504 | 0.7797 |
| 保守检测 F1 | 0.9204 | 0.8333 |
| 平均耗时 | 12.87 秒 | 18.93 秒 |
| 外部调用次数 | 96 | 173 |
| 已报告 token | 110281 | 219808 |

**结果解释：**

1. 本次结构化组全样本主类别准确率低于基线；复核提高了拒判比例与调用开销，不能据此宣称诊断能力整体提升。  
2. 两组失败分别为 6 次与 8 次，均为模型超时。  
3. 若将待复核视为流程有效，流程完成率分别为 92.41% 与 89.87%，仍低于计划中 95% 的参考目标。  
4. 结果保持原样，不删除失败样本，不在同一测试集上调参后重新宣称独立成功。  
5. 两组合计 269 次外部调用、已报告约 33 万 token；未报告用量不等于无费用。修改质量人工评分与完整方案实验尚未完成。

上述结果只说明该模型、该测试集、该配置下的单次对照表现，不能外推为跨模型或跨人群的普遍结论。

### 8.4 工程验证

自动化测试覆盖接口兼容、八类固定样例、正常句、超时与格式错误、修改判分、事务回滚、未审核题目的导入保护、精确推荐、错题解析与近期画像等，完整回归通过。测试在强制演示或注入响应条件下运行，不产生真实模型费用，因此测试通过不等于语文准确率。前端生产构建通过；浏览器完整操作验收通过。真实模型单句冒烟仅证明服务连通与复核流程，不能替代 79 条正式对照。

## 9 质量保障与运维要点

系统在接口层与智能体层双重校验数据结构；为每次请求分配请求编号，并将参数错误、模型错误、数据库错误映射为统一错误语义。演示模式只覆盖明确固定样例，未知输入必须待复核。演示库与正式库路径隔离，避免互相覆盖。课堂演示可使用离线闭环展示交互；真实实验表格与失败、拒判案例单独说明，二者不得混为同一证据。

## 10 结论与展望

MistakeMind 实现了面向中学生的病句诊断与个性化训练闭环：结构化诊断与分层提示、三题型判分、事务化错题记录、确定性推荐与画像，以及可解释的执行轨迹。其工程价值在于把大模型约束在语义子任务内，用结构校验、预算控制、复核门控与数据隔离降低不可控输出进入成绩与正式题库的风险。真实对照实验进一步表明：增加结构化约束与复核并不自动带来全样本准确率提升，必须以接受、拒判、失败与耗时一并报告。

主要局限包括：修改有效性与原意保持尚未完成系统人工评分；完整方案所需的无泄漏工具题库与历史场景仍待准备；缺少完整认证、教师端与长期学习效果因果验证；置信度未校准；服务超时仍影响流程完成率。后续可在独立开发样本上优化超时与复核策略，完成修改人工评分与完整方案实验，并在实际课堂环境完成演示彩排。

## 11 团队分工与工作比例

项目按前端、智能体、题库评测、后端部署四个模块组织开发。四人工作比例均为 **25%**，职责对等、交付互补。

| 成员 | 工作比例 | 主要职责 | 贡献要点 |
| --- | ---: | --- | --- |
| A | 25% | 前端与学生训练流程 | 训练与诊断页面，三题型交互，历史与画像展示，错误提示与演示动线 |
| B | 25% | 智能体、提示词与诊断判分 | 路由、诊断、提示、修改、答案分析与复核，提示词版本，超时与低置信处理，实验中的诊断流程 |
| C | 25% | 题库、推荐与评测 | 练习题与评测样本组织，标签与难度规范，审核导入规则，平滑推荐与画像口径，对照指标与失败分析 |
| D | 25% | 后端、数据库与部署 | 统一接口与数据模型，事务落库，异常处理，本地启动与部署配置 |

A 保障可用性入口，B 保障可解释的语义能力，C 保障可教学与可度量的数据基础，D 保障可集成的系统骨架。四者共同构成 MistakeMind v1.2 的完整应用，工作比例为 **25% : 25% : 25% : 25%**。
