# 基于大语言模型与练习反馈的病句诊断智能体设计与实现

## 摘要

MistakeMind 面向中学生病句专题训练，将句子诊断、学生作答评判、修改解释、记录保存和针对性复练组织为一个 Web 学习流程。系统采用 Vue 3、FastAPI、Pydantic、SQLite 和兼容 Chat Completions 的大模型服务。模型负责语义分析和教学反馈，确定性程序负责请求校验、题库读取、事务保存和统计推荐。工程实现覆盖八类病句与正常句，包含项目计划要求的四类目标语病。本文说明系统边界、接口与数据设计、质量控制和评测方法。自动化回归与真实模型实验分别报告，避免把固定 Mock 的工程结果当作诊断精度。

## 1 任务背景与范围

普通病句练习通常给出标准答案，难以解释学生本次作答错在哪里，也缺少连续学习记录。通用语言模型可以生成改写，却可能过度修改、改变原意或把正常句当成病句。项目目标是提供可追踪的诊断与复练流程，并保留不确定判断。

核心使用方式包括自主输入句子、完成分类或修改题、查看错题解析及学习统计。实现支持成分残缺、成分赘余、搭配不当、语序不当、结构混乱、表意不明、不合逻辑和关联词使用不当。额外类别不替代计划要求的四类验收。用户采用虚构单用户标识；OCR、模型微调、教师端和复杂知识图谱不在本期必做范围。

## 2 系统架构

前端以 Vue Router 组织首页、诊断、答题、历史和画像页面。统一 API 客户端解析 success/data/error/meta 响应，异常状态由通用组件呈现。浏览器不直接访问模型服务，也不计算推荐优先级。

FastAPI 提供请求校验、业务编排和统一错误处理。后端将输入封装为 AgentContext，携带任务、年级、原句、学生答案、历史摘要和执行轨迹。AgentService 使用确定性主控组织逻辑阶段，而不要求每个阶段都单独调用模型。

SQLite 保存用户、题目、作答、诊断和题目教学详情。题库和评测集由 JSON 文件维护，导入时校验字段和审核状态。生产构建将 Vue 静态资源交给 FastAPI 同源提供，开发环境通过 Vite 代理调用接口。

## 3 诊断与作答评判

### 3.1 结构化诊断

诊断输出包含 has_error、error_types、error_span、explanation、corrections、hints、confidence 和 needs_context。正常句返回空错误类型和修改列表。标签固定为统一枚举，禁止将知识点子标签随意变成新类别。模型输出先经过结构与一致性校验，再由复核调用检查分类依据、错误消除、原意保持和提示完整性。

输出不可靠、需要上下文或未达到自评门槛时返回 needs_review。前端将此状态显示为“暂无法确认”，避免布尔 has_error 字段造成过度确定的结论。自评 confidence 不等价于校准概率。

### 3.2 最小修改与分层提示

病句可以返回多个合理修改。修改目标是消除原语病并尽量保留原意；提示按观察位置、知识点、修改方向分三级。正常句不强行生成提示。模型生成与复核共用请求次数和总时间预算，格式修复与网络重试也计入预算。

### 3.3 学生答案评判

判断题和分类题依据已启用题目的标准标签评分。修改题先接受符合参考的修改，其他表达由语义评判和复核共同判断。原病句原样提交不能判对；缺少上下文、题目依据矛盾或复核不通过时不计入成绩。

作答成功时返回保存的关联 diagnosis，前端直接展示本次反馈，不通过另一次自由诊断覆盖判题依据。trace 包含判分、保存和推荐事件，便于解释模型和程序分别完成的步骤。

## 4 数据与持久化

questions 存储题面、题型、类别、参考修改、难度和启用状态。question_details 补充教学解释及错误片段，采用附表保留旧题目表兼容性。attempts 记录学生答案、正确性、提示等级、尝试次数与时间；diagnoses 关联本次作答的错误类型、解释、修改和复核状态。

作答与诊断在同一数据库事务中保存，任何一步失败都回滚。历史页按用户查询，支持分页、类别筛选和只看错题，显示原句和保存时的解析。浏览器刷新后重新读取数据库。此项目为单用户课程演示设计，user_id 用于分组记录，并不构成完整认证授权系统。

题面接口不返回参考修改或解释，category 兼容字段返回 null，避免分类选择题直接暴露答案。完整解析仅在作答后提供。

## 5 个性化推荐与画像

推荐采用最近 50 次作答作为近期窗口。某类别有 n 次作答、e 次错误时，C 规则给出平滑错误率 (e+1)/(n+2)，并加入 0.15/(n+1) 的探索奖励。线上先确定优先类别，再在该类别内避开近期题；同类题数量不足时允许复练。推荐保持本次题型和难度，返回的题号由前端精确获取。

画像保留累计正确率和错误次数，近期表现使用 (c+1)/(n+2) 估计，其中 c 为窗口内该类答对次数。少于 3 次时标注样本不足，避免根据一次作答宣称长期能力。每日趋势显示最近 14 个有作答日期的题数和正确率；其变化只说明练习记录变化，不构成学习效果的因果证据。

## 6 数据准备与隔离

当前练习目录包含原有 20 道候选和 44 道初高中书面语题型变式，共 64 道不同候选。这些内容保留 pending、未启用，需逐题人工教学审核。来源与选材说明位于 data/README.md 和 school_sources.json；自编变式不称为历年真题或教材原题。

正式评测集为 b-reviewed-1.1，共 79 条 approved 样本，其中 61 条病句、18 条正常句，包含八类覆盖和 8 条多标签。评测集不导入练习数据库。原始候选及审核修订档案保留以便追溯。

另设独立开发演示库，由既有 12 个固定 Mock 句子组成三种交互形式，共 36 道演示题。此库只用于工程与课堂流程演示，不计入人工审核语料规模，不用于正式模型精度结论。

## 7 评测设计

Baseline 使用通用诊断指令；结构化方案增加固定标签定义、教学约束和独立复核；完整方案再引入独立工具题库和虚构历史场景。为便于自动解析，基线也使用同一 JSON 输出契约，因此比较的是通用指令与专用流程，不是任意自由文本聊天。

运行器逐条保存成功、拒判、失败、耗时、调用轨迹和上游报告的 token。恢复运行要求数据、上下文、配置和代码哈希一致；失败重试保留原记录。整体准确率、分类 Macro-F1 以全部样本为分母；被接受样本的指标另列，不能代替整体结果。检测的保守计分将拒判病句计 FN、拒判正常句计 FP，需与标准二分类混淆矩阵区分。

修改有效性和原意保持由人工逐个评分；推荐命中率需要独立场景中人工确认的目标类别。费用按供应商实际账单核算。正式 full 实验要求工具题库已审核、与测试集无同题或近似泄漏，不能使用待审核题或最终测试答案补足。

## 8 工程验证与实验结果

当前 v1.2 完整回归为 210 项通过，覆盖旧接口、八类固定样例、正常句、超时和格式错误、修改判分、事务回滚、审核导入保护以及新增精确推荐、错题解析和近期画像。前端生产构建通过。真实模型正常句冒烟完成了诊断与独立复核两次调用，并返回 passed。详细实验指标与实际失败案例集中记录在 docs/EXPERIMENT_RESULTS.md，浏览器记录见 docs/BROWSER_VERIFICATION.md。

工程测试证明相应分支在测试条件下按预期工作；真实模型的单次冒烟只证明服务兼容与该样例流程。模型准确率、稳定性和教学质量必须结合完整实验和人工评分解释，不能从测试数量推导。

## 9 部署与异常处理

start.ps1 提供本地完整应用启动和独立演示模式。Docker 采用 Node 前端构建与 Python 服务两阶段，运行时通过环境文件和 data 挂载提供配置及持久化。构建上下文排除密钥、数据库、Git 与测试输出。

模型调用设单次超时、总时间和次数预算，网络或服务端异常有限重试，JSON 错误有限修复。真实服务失败不会静默切回 Mock。模型不可用、超时、非法 JSON、数据库异常和参数错误使用统一错误码。课堂备用演示明确标识为离线固定样例。

## 10 成员分工与局限

A 对应前端和交互，B 对应诊断与判分，C 对应题库和推荐评测，D 对应后端、数据库和部署。以上为职责划分，不直接证明每人完成 25% 的实际工作。最终贡献应根据代码提交、测试记录、文档和现场展示核对。

仍需逐题审核独立练习题，完成真实修改人工评分，准备正式完整方案所需的工具题库与场景，并在课堂实际环境彩排。本项目不声称已经证明长期学习收益，也不将近期正确率视为学生认知能力的精确测量。
