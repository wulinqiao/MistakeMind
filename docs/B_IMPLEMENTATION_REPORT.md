# 成员 B 核心诊断模块实现与展示

## 实现结果

B 模块将原先的关键词 Mock 接口替换为可配置的模型适配器和确定性业务流程。系统按任务进入诊断或作答路径，诊断生成错误类型、依据、修改及提示，再独立复核；学生修改不必与参考逐字相同，但需满足语病消除、原意基本保留和无新错误。

工程上复用 FastAPI、Pydantic、httpx 和 SQLite，没有引入新的 Agent 框架。逻辑阶段包含路由、诊断、答案分析、提示、修改、复核，常规诊断通常只需两次模型调用。选择题及参考修改直接使用审核后的标准判定，避免不必要的模型调用。

## 对系统闭环的贡献

新增真实调用配置、超时和总预算、错误映射、结构校验、Prompt 版本和脱敏轨迹。API 继续兼容原有路径，补充 needs_context，保留复核状态。无法确定的修改不会记为答错，也不会更新画像。作答与关联诊断在同一事务保存，历史可以查到本次错误类型。取题不再把参考修改当选项返回。

联调暴露了 Windows 下数据库连接持有文件句柄的问题；Database 自有连接现在显式关闭，并验证保存失败会完整回滚。未更换前端、推荐算法或现有数据库表结构。

## 实验准备与结论边界

初始准备八类各 8 条病句、16 条正常句，共 80 条候选测试样本；另有 17 条开发回归样例。人工审核完成后导出 79 条 approved，b_eval_038 淘汰，b_eval_043 与 b_eval_047 按用户确认改为正常句。当前 b-reviewed-1.1 正式集包含 61 条病句、18 条正常句和 8 条多标签，保留八类覆盖；原始候选仍保持 pending。实验入口覆盖普通 LLM、结构化诊断与复核、带工具题库和历史的流程，逐条记录成功、拒判与失败，保留恢复和重试依据。

已完成的验证说明接口、判题分支、校验、错误处理与持久化可以在离线条件下运行。人工审核测试集已经就绪，真实模型尚未配置，因此没有真实精度、修改质量、延时或费用结论。正式报告应在真实调用和人工修改评分后填入指标、样本规模和失败案例，不预设模型优于基线。

## 课堂讲解稿 60—90 秒

我负责核心诊断和学生答案分析。系统先按任务进入诊断或答题流程，再检查模型给出的类型、证据和修改是否一致。诊断、修改和三级提示共用一次生成，另一次调用负责复核，所以逻辑阶段多并不意味着每次都要调用六遍模型。

修改题不仅比较参考答案。参考以外的合理表达也可以通过，但必须消除语病、保留原意且没有新错误。如果缺少上下文或复核不同意，系统提示人工复核，本次不计成绩，避免影响后续画像。

演示中可以看到一次诊断、一次作答、真实数据库中的关联诊断和下一题推荐。当前这些验证采用离线样例；真实模型效果需要在人工审核的独立测试集上比较普通模型与专用流程，并同时报告拒判、失败和典型误判，不能把测试通过当作精度结论。
