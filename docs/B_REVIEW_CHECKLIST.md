# B 模块候选评测集人工审核

目标是形成独立、可解释的人工标准。80 条样本均为 AI 辅助编写候选，结构通过不等于教学审核通过；程序不会自动填写 approved。审核由项目组具备相应语文知识的成员实际完成，争议项建议两人复核。

对每条候选检查：

1. 句子适合初中学习场景，单句上下文足以完成所设任务；正常句确实无需强行修改。
2. has_error 与解释一致，主类别 category 在 error_types 中；子标签不代替统一类别。
3. 多标签确有独立错误依据，不能为了数量把同一个错误重复分类。八条预设多标签尤其需检查。
4. error_span 能定位问题；修改消除语病、基本保留原意且没有新语病。
5. 对表意不明等句子，说明不同解释并补充可接受修改；不能把缺少依据的唯一改写当标准。
6. 核对来源、AI 辅助标识和许可说明。没有来源证明时不能填为引用教材或公开数据集。
7. 与开发样例、Prompt 示例、工具题库及其近义改写隔离；审核完成后再运行真实测试。

审核操作：修改语义标注后填写 review.reviewer、review.reviewed_at（ISO 8601）和 notes；同意设 approved，不同意设 rejected，未确认保持 pending。不要为了通过检查批量批准。保留原候选文件，另存人工 reviewed 版本用于正式实验；测试集不需要 is_active=true，也不要导入练习数据库。

正式导出只包含已批准记录，至少 60 条，覆盖八类与正常句；报告如实列出各类数量和多标签数量。若淘汰后不足，应补题、复核并生成新数据版本。

## 修改质量人工评分

先阅读原句、目标语病和模型修改，再为每个 correction_index 独立填写：

| 字段 | true 的条件 |
| --- | --- |
| effective | 原语病已消除，未引入新语病 |
| meaning_preserved | 基本保留原句意图，没有以大幅删改回避问题 |
| reviewer | 实际评分人，不能用模型名称或脚本代替 |

无法确定时保留 null 并在 notes 中说明。最终同时报告修改总数、已评分数和两个比例；不能只挑成功案例评分后宣称整体效果。
